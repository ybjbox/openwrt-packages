## 3. 三条机制陷阱（最容易让人做出错误决定）

### 3.1 运行时单文件，源码在 `view-src/`（r130 起）

抓这份文档的人最容易踩的一条：**`luci-app-cf-ipcheck/src/` 这个目录名不能用**。
luci.mk 的 install 段只要看到包内有 `src/`，就认定它是编译型源码包，会额外调用
`Build/Install/Default` 并复制 `$(PKG_INSTALL_DIR)/*`；我们的 view 源码没有安装产物，
于是 cp 空目录失败，构建只剩一句 `failed to build`（`V=s` 把细节吞了）。
→ 源目录叫 **`view-src/`**，构建脚本把 `manifest.txt` 里的文件按顺序拼成运行时单个
`htdocs/.../settings.js` 与 `settings.css`。

因此：
1. **产物不手改**。改 `view-src/` → 跑 `sh tools/build-view.sh` → 两个产物一起提交。
   `sh tools/build-view.sh --check` 会逐字节比对并与 `PKG_RELEASE` 对齐。
2. 运行时仍是单文件（uhttpd 每多一个 JS 就多一次请求），所以 `require` 语义、
   多文件加载成本这些约束照旧不适用 —— 拆分只发生在作者侧。
3. CSS 只允许一个源文件（`view-src/style/00-app.css`）：CssTidy 会合并选择器，
   多文件时「文件顺序即优先级」在构建后不可依赖。
4. 构建脚本会拦 ES5 以外的语法（`=>`、`let/const`、反引号、展开运算符）——
   JsMin 是字符级压缩器，不认这些边界。

### 3.2 i18n 对页面主体完全失效

`build/i18n-scan.pl` 对 `.js` 的关键字**只有** `_:1` / `_:1,2c` / `N_:2,3` / `N_:2,3,4c`，
**不认自定义包装**。视图里 `T(...)` 共 **265 处**，一个都提取不到；`_()` **218 处**和 menu.d 的 title 能提取。

**后果**：一旦加 `po/`，只有表单和菜单被翻译，页面主体永远中文 —— 半翻译比不翻译更难维护。
包内目前**没有** `po/`。

**如果非做 i18n**：机械替换 `T(` → `_(` 是安全的 —— 实测 **265 处全在代码区、0 处在字符串字面量里**。

复核这个数字用（`grep -o 'T('` 会把字符串里的也算进去，不能用）：

```sh
node E:/cf_ipcheck/lint-trial/count-i18n.cjs \
  E:/cf_ipcheck/feedclone/luci-app-cf-ipcheck/htdocs/luci-static/resources/view/cf_ipcheck/settings.js
```

### 3.3 构建期会改写你的代码

| 机制 | 行为 | 约束 |
|---|---|---|
| `luci.mk` 的 `JsMin`（jsmin） | **字符级**压缩器，不认模板字符串这类语法边界 | 保持 ES5 写法（`var` / `function`），不引入箭头函数、模板字符串、`let`/`const` |
| `CssTidy`（csstidy） | 合并选择器 | CSS 不靠源文件顺序表达语义 |
| 资源版本参数 | 视图用 `L.resource()` 挂 JS 与 CSS，设备上 `luci.js` 把它拼成 `` `${path}?v=${env.resource_version}` `` —— 两者**都有** `?v=`，但那个值来自 **luci-base**，**不跟本包版本走** | 升级本包后 URL 不变 → 浏览器可能吃旧 JS/CSS，**必须硬刷新（Ctrl+Shift+R）**。真实缺陷是"版本值不跟本包走"，**不是"CSS 没有版本参数"**（旧版文档这里写错，2026-10-26 实测更正）。对策：想按包版本破缓存要**换值**（`?v=VIEW_BUILD`），而不是"补一个缺失的参数" |

**因此每次前端出包后要过一道关卡**：把设备上已安装的压缩版取回来做语法检查。

```sh
scp root@10.0.0.1:/www/luci-static/resources/view/cf_ipcheck/settings.js ./min.js
node -e 'new Function(require("fs").readFileSync("./min.js","utf8")); console.log("PASS")'
```

### 3.4 构建环境的真实卡点（r177，必须知道）

r177 的三次 SDK 构建都曾在 `Build with OpenWrt SDK` 里卡 40～80 分钟；
**不是代码、不是 CssTidy、也不是 `:is()`**。成功日志显示 `setup.sh` 的 GPG 校验后要下载
**244MB 的 SDK 包**（r176 成功时约 6 分钟）：

```

```

当前 GitHub runner 到 `mirror-03.infra.openwrt.org` 的大文件下载会长时间无进度；
25.12.5 与 25.12.2 的 setup 都会卡。最终 r177 是等 25.12.2 下载完成后构建成功的
（run `42447242831`）。接手时的判断顺序：

1. 先看 build job 是否停在 `setup.sh`/GPG 之后——那是 SDK 下载，不是编译；
2. 不要因为 view/lint 绿就以为包快好了；
3. **dispatch 用与设备一致的 `aarch64_cortex-a53-25.12.2`**，不要用默认 25.12.5；
4. 如果 40 分钟无产物，先看是否真的卡住，别把卡住的 run 当“正在编译”。
   ⚠️ **r178 实测修正**：run `42465520660`（同样 25.12.2）耗时约 **234 分钟**才成功，
   三个 job 全绿、全程无失败步骤；r177 成功那次也是 109 分钟。所以 40 分钟只是「开始留意」，
   **不要机械取消**——两个测试 job 已绿、build job 无失败且 runner 存活时，继续等比重派更快
   （重派要重新排队下载 244MB）。真要取消，先确认 build job 停在 `setup.sh`/GPG 之后且长时间无进展。
   ⚠️ **r179 实测补充**：run `42550506880`（同样 25.12.2）约 **15 分钟**就三 job 全绿，
   说明 SDK 缓存命中时很快；耗时在 15～234 分钟之间大幅波动，唯一可靠判据是
   「测试 job 已绿 + build job 无失败 + runner 存活」，不是固定分钟数。

另外：`gh run view --json status,conclusion` **不能**接 `--jq -r`（会被当成两个参数，
报 `accepts at most 1 arg(s), received 2`）。用 `--template '{{.status}} {{.conclusion}}'`，
或 `--jq '.status + " " + .conclusion'`（不要 `-r`）。

### 6.5 DNS 自动解析（r96–r99 新增）

配置 `dns_targets`（多行文本框，uci 里存分号分隔单行）：

```
cf.example.com 3          ← 记录名 + 数量（挂几条 A 记录，DNS 层即轮询）
www.example.com 1
api.other.net 2 other.net ← 行尾可写自己的 zone
```

写策略是**集合 diff**：缺失的 POST、**本工具建的**（`comment=cf-ipcheck`）且不在期望内的 DELETE、
其余不动。他人手工建的记录一律不碰，只在日志里报「另有 N 条非本工具管理的记录未动」。

**去重 ≠ 跳过核对**：本机 `dns-zones` 缓存只省"按 zone 名查 id"那一次请求，
**不省**"读现有记录" —— 只有真读一次才能发现记录被面板手改过，下一轮才能自愈。

三个入口分开：自动收尾守 `dns_sync` 开关 / 页面按钮 `--manual`（绕开关但仍去重）/
ssh `--force`（连去重也绕，真去问一次）。

**写路径的三条不变量（r101 起，改这里之前先读懂）**：

1. **先加后删**。新增成功之后才删多余的旧记录 —— 反过来（先删后加）一旦新增失败，
   这个记录名的 A 记录就少几条甚至空掉，等于把解析写挂。中间那一小会儿多一两颗
   "旧但当时可用"的 IP，DNS 轮询无碍。
2. **单实例**。`mkdir` 原子锁（BusyBox 没有 flock）守在 `$RUN_DIR/dns-sync.lock`；
   自动收尾与页面按钮是两条独立路径，同时算 diff 会各自基于同一份旧快照 POST/DELETE。
   持有者 pid 已死或超过 600 秒可被接管；抢不到按 **退出码 2** 退出（脚本自己记了原因）。
3. **删除只记 IP**。删除成功只写一行 `删除 <IP>`；proxied/ttl/comment/id 不再刷进主日志
   （日志页太杂）。重建所需信息 = 这个 IP + 本工具固定写死的 proxied=false / ttl / comment。
   回读校验还会抓"本工具建却不在期望里"的残留（`_extra`），发现删不掉就 `return 5`。

## 7. 踩过的坑（症状 → 根因 → 修法）

### 7.1 引擎与后端

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 页面永远"从未运行过" | `expect:{stdout:''}` 已拆出 stdout，代码又取 `res.stdout` → 恒 undefined | 直接用返回的字符串 |
| 2 | ACL 拒绝时像"没结果" | `rpc.declare` 失败返回 `''`，与"跑了没结果"同形 | 失败一律返回 `null` |
| 3 | 配置静默失效 sources=0 | rpcd 子进程 PATH 里没有 `/sbin` | `find_bin` 按绝对路径候选逐个试 |
| 4 | 同上但 uci 找得到 | uci list 打印有第四种形状 `opt='a' 'b' 'c'` | `uci_list_parse` 用 `tr ', \t'` 一起切 |
| 5 | 126 候选里 112 个假性 `transport_23` | 运行目录 700，nobody 进不去 | `chmod 711` + 开跑前以探测身份真写一次 sink |
| 6 | 陈旧锁卡死后续轮次 | 只看锁文件在不在 | 锁写 `<pid> <启动秒>`，`kill -0` + 6h 上限 |
| 7 | `valid_ip4('')` 通过 | awk 空输入仍退出 0 | 先 `case ''\|*[!0-9.]*)` 挡 |
| 8 | 脏配置打死 shell | `$(( ))` 遇非数字 | `cfg_num` / `cfg_range` 夹取 + 记日志 |
| 9 | `cut -d' ' -f2` 返回整行 | 无分隔符时 cut 的行为 | 改 `awk -v f=N '{print (NF>=f?$f:"")}'` |
| 10 | 输出重定向失败打断整轮 | 重定向失败是 shell 级错误 | 包进 `( … ) 2>/dev/null \|\| true` |
| 11 | **多点 IP 只读到一半** | `sed -n 's/...#...//p'` 的 `p` **只打印发生过替换的行**，裸 IP 行匹配不到就被丢掉 | 改用 awk。**单 IP 时代只读第一行所以从未暴露** |
| 12 | 写 DNS 一直"没有回应" | rpcd 平台级 30 秒上限，一次同步 4 个请求 × 20 秒 = 80 秒被掐断 | 单请求 `--max-time 4` + 整次预算 25 秒，超时自己停手并记日志 |
| 13 | 改了 uci 的 option 值把配置文件写坏 | **uci 的 option 值不能含换行** | 列表在 uci 里存分号分隔单行，页面保存时转换 |
| 14 | 迁移脚本"找不到" | `/etc/uci-defaults/90-cf-ipcheck` 在包安装执行后**自动删除** | 要重跑得从包里再解出来 |

### 7.4 目标设备的硬事实

1. rpcd 子进程 PATH 里没有 `/sbin` → `command -v uci` 失败（表现为“配了源但引擎按默认值跑”）。
2. `/dev/null` 在这台机器上是**普通文件** → 写进去真占文件系统 → `curl rc=23`。
3. procd 进程 umask 077 → `mkdir /tmp/cf-ipcheck` 出来是 700，nobody 进不去。
4. uci 打印 list 有第四种形状（见坑 4）。
5. 这台机器的 LuCI 没有 toast API。
6. `form.js` 里没有 `collapsible` → 节折叠要视图自己做。
7. `stat` 不可用 → `diag` 里 `run_dir_mode` 是 `?`。
8. BusyBox 方言坑：`cut` 无分隔符返回整行；`awk` 空输入退出 0；`$(sh -c 'echo $PPID')` 不加 `exec` 记到瞬时 pid。
9. rpcd 平台级外部执行上限 **30 秒**（`file.exec` 与 ucode 方法共用）。
10. 设备当前是 LibWrt 25.12.2 / aarch64_cortex-a53；apk-tools 3.0.5；
    **打包用 25.12.2 SDK**，不要用 25.12.5（SDK 下载卡，见 §3.4）。

**桩测环境要点**：

- `String.prototype.format` 必须补进 stub（LuCI 全局加了它）→ **只实现 `%s`**，
  所以视图代码一律用 `%s`。r100 已把最后 4 处 `%d` 清零，并加了一条断言钉住
  （反向验证过：塞回一个 `%d` 会红）。
- `E()` 的 stub 要带 `style={}`、`appendChild`、`setAttribute`、`addEventListener`
- 断言"渲染出的文字/列数/类名"，不依赖真实 DOM
- **新加断言要做反向验证**：把它对应的代码改坏，确认测试真的会红（否则断言可能空转）

**跨容器可移植两坑**（lint 与 CI 脚本里到处是 awk，最容易踩）：

- **awk 动态正则里的字面圆括号必须写 `[(]`** —— `\(` 在 gawk 的动态正则里被当成未转义分组，整段 awk 直接 fatal
- **量中文长度必须 `LC_ALL=C`** —— gawk 在 UTF-8 locale 下 `length()` 数的是字符数、
  busybox awk 数的是字节，不钉住 locale 的话同一条阈值在两个 CI 容器里量出来的数**差三倍**，
  断言就成了看运气。red-line-7 的"短句 ≤160 字节"就是靠这个才稳定的。
