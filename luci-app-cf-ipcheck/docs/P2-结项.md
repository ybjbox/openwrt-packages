# P2 跨轮稳定性实验 · 结项

> 目的只有一个：**回答「同一批 IP 跨时段测速，排名能不能复现」**。
> 结论已于 2026-11-20 三次访问后收敛，实验到此结束，不再增加访问。
> 原始数据与脚本在仓库外的 `E:/cf_ipcheck/`（`p2-data.tsv`、`p2-stability.sh`、`p2-analyze.py`、`p2-extended.py`）。

## 方法

- 固定 8 颗 IP（`172.64.229.{5,6,8,10,11,19,21,26}`），每颗 2 遍，单遍 10 MiB，间隔 40 s，每次访问先预热 2 次。
- 三次访问：11:13–11:24、14:42–14:53、16:00–16:12，共 **48 样本**，全部 HTTP 200、字节满额、无 429。
- 只调用 `cf-ipcheck test-ip <ip> speed`：不写 `result.json`、不写榜单、不推 Gist、不动 DNS、不改配置。

## 结果

| 指标 | 数值 |
| :--- | :--- |
| 合并样本 SD / CV | 2.11 MB/s / 17.0% |
| 单次测量 95% 区间 | **±34%** |
| 每颗 IP 六样本极差 | 中位 43.6%（最大 56.5%） |
| 访内离散中位 / 跨访离散中位 | 23.5% / 16.1%，比值 **0.68** |
| 访间方差 vs 访内噪声 | F=0.48（F(16,24) 临界 2.24）→ **无时段漂移证据** |
| 访间 Spearman | 1v2 +0.357、1v3 −0.310、2v3 −0.048，**全部不显著**（\|t\|<2.447） |
| 8 颗 IP 六样本区间 | **全部重叠**，共同交集 [10.23, 13.51] |
| 引擎口径相邻名次间距 | 0.09~0.59 MB/s（0.9%~5.5%） |

**判定**：名次间距比单次测量误差低 1~2 个数量级，三次访问的榜首分别是三颗不同的 IP（一致 0/3）。
**单遍 10 MiB 无法区分任何两颗 IP，跨轮排名不可复现。** 主因在测量本身，不在链路。

## 由此产生的改动（r224）

原「两遍取较差的一遍」在实测数据下是**系统性偏低**，不是保守：

- 两遍的实际落差可达 0.38（14:00 轮 `result.json` 的 `speed_spread` 为 0.186 / 0.382 / 0.382），
  取小值等于「只要有一遍掉进低模态就按低模态记账」。
- 不稳的 IP 已经在 `speed_spread` → `stab_of()` 里单独扣过一次分，取小构成**双罚**。
- 因此 `speed_merge()` 改为取两遍均值；`spread` 仍按 `|max−min|/max` 计算，语义不变。

`speed_samples` / `speed_spread` / 门槛 / 排序 / 页面 / CSV / Gist 的口径全部不变，仍统一由
`speed_merge()` 产出。

## 未回答的问题

- **第二遍为什么偏低**：把对间距从 40 s 拉到 120 s 并未消除它（5 对中 4 对仍偏低，中位 −34%），
  所以不是「短窗口回补」。该实验在第 13 次下载触发 429 中止，样本不足，**机制未定**。
  若要继续，建议做顺序反转（同一 IP 连测 4 次），区分「第 2、4 次低」（奇偶）与「后半段低」（累积）。
- 无论如何，**该答案不改变任何代码分支**——这是停止实验的主要理由。

## 顺带确立的运维规则（对所有测速实验有效）

429 由**累计字节量**触发，与请求间隔无关：

| 时段 | 本段 | 滚动 60 min 内累计 | 结果 |
| :--- | :--- | :--- | :--- |
| 11:13 访问 1 | 18 次 / 189 MB | 189 MB | 无 429 |
| 14:42 访问 2 | 18 次 / 189 MB | 189 MB | 无 429 |
| 16:00 访问 3 | 18 次 / 189 MB | 189 MB | 无 429 |
| 16:18 间距实验 | 14 次 / 147 MB | **315 MB** | **429** |

阈值约 **270~330 MB / 滚动小时**（27~31 次 10 MiB 下载）。单次访问 18 次是安全的，
**同一滚动小时内不要跑两次完整访问**；拉长间隔无助于规避，只会让窗口占用更久。
